## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
heaptide finds leaks in CPU, GPU (HIP and Mojo) and Python programs in one pass, without
rebuilding them. On an 8-thread malloc benchmark it runs 12x faster than heaptrack with 6.7x less
added memory. On every planted leak in its test suite, its direct/indirect split matches
LeakSanitizer's. It also sees HIP device and pinned host memory, Mojo's GPU buffers included,
which no other leak tool we know of covers on ROCm.

```
heaptide run [--gpu] [--py] [--py-depth N] [--every MS] [--snapshot-every S] [--out DIR] -- CMD...
heaptide snapshot DIR
heaptide report DIR [--json] [--top N] [--supp FILE] [--fail-on any|leaks|growth|none]
heaptide attach PID [--out DIR]  ·  heaptide detach DIR  ·  heaptide diff BASE NEW
```

## Highlights

<!-- 1 to 5 bullets a user would notice. Lead with the benefit, not the implementation. -->
- `GPU SCRATCH`: the device memory the ROCm runtime holds for register spills and private arrays is named per kernel
  (it showed as "device: held beyond live blocks" before); `--kernels` keeps only the dispatched kernels.
- GPU blocks allocated from Mojo name the Mojo call site, not the runtime frame.
- `report --gui` long lines stop inside the panel.

## Changes

### Added
- `GPU SCRATCH` report block: per AMDGPU code object of the exe (llvm-readobj), the per-queue scratch from the ROCr
  formula in `docs/scratch.md`; `--kernels KERNEL_TRACE.csv` (rocprofv3 `--kernel-trace -f csv`) keeps the dispatched ones.
### Changed
- The symbolizer runs with `--inlines`: a site is the outermost frame in the user's own source, inlined callers are listed.
### Fixed
- A stripped Python interpreter's symbol-only frames no longer count as user code (the site chain stopped before
  the `py::` frame on ubuntu's python3.12).
- `report --gui`: long lines are clipped 8 px inside the border; under gpu-wait the window drops
  `HSA_OVERRIDE_GFX_VERSION`, which made ROCr find no device.

## Known limits

<!-- Honest list: slow paths, unsupported cases, flaky upstreams, anything UNVERIFIED. -->
- `GPU SCRATCH` is computed from the ROCr formula and the code objects, not read from the driver.
- `--gui` needs a GPU, SDL3 and `mojo-imkit` next to the repo at build time; the CLI needs none of them.
